CLAUDE DAILY TEFAS DATA RULE — V2

Use the GitHub-generated TEFAS files in this order:

1) TEFAS_SCREENING_REPORT.md
   - This is the primary daily quantitative pre-screen.
   - It is generated programmatically from the full TEFAS_DAILY_DATA.csv universe.
   - Treat it as STAGE 1, not as an investment recommendation.

2) TEFAS_SHORTLIST.csv
   - Contains the same top quantitative candidates in structured form.
   - Use it for candidate-by-candidate comparison.

3) TEFAS_SCREEN_STATUS.json
   - Use it to confirm dataset date, universe counts and shortlist generation success.

4) TEFAS_DAILY_DATA.csv
   - This is the full dataset.
   - In Claude Project Knowledge it may be accessed through RAG/chunk retrieval, so DO NOT claim you programmatically scanned the whole CSV yourself.
   - Use it mainly for targeted lookups of specific fund codes when useful.

DAILY PROCESS

A. First verify TEFAS_SCREEN_STATUS.json and dataset freshness.
B. Read the pre-ranked candidates in TEFAS_SCREENING_REPORT.md / TEFAS_SHORTLIST.csv.
C. Perform fresh web research on the strongest candidates.
D. Prefer primary sources: KAP, TEFAS, fund manager disclosures, official macro sources.
E. Verify retail investability before calling any candidate actionable.
F. Check portfolio overlap and concentration against CURRENT PORTFOLIO.
G. Compare any proposed deployment of capital with the user's current deposit benchmark.
H. Do not recommend a fund merely because the quantitative script ranked it highly.
I. If the report is stale or generation failed, explicitly say so and do not present it as a fresh full-universe screen.

The full-universe quantitative scan is performed by GitHub Actions/Python.
Your role is to interpret, validate, research, compare and make portfolio-level judgments.
